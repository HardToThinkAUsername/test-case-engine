## 这是什么

一个 **Claude Code Skill**。安装后，AI 编程助手就获得了"测试用例生成"能力——你给需求，它给用例，对话式、可调整、输出 Excel。

**为什么不直接对 AI 说"帮我生成测试用例"？** AI 写用例看起来全面，实际上会遗漏大量边界场景。这套 skill 提供了一套方法论——业务树建模、L1-L4 分层覆盖、5 维度需求评审、10 种想象力增强技术——确保生成的用例系统化、无遗漏、无冗余。

## 它能做什么

| 能力 | 产出 | 说明 |
|------|------|------|
| 业务建模 | 业务树（入口点、流程、分支点） | 4 类入口点 + 决策树 + 中文表述模式库 |
| 需求评审 | 5 维度问题清单 | 完整性、一致性、清晰性、边界性、异常性 |
| 测试大纲 | 按模块组织的测试点，标注优先级和来源层级 | L1-L4 分层覆盖 |
| 生成用例 | 完整用例（编号、步骤、预期结果、关联需求） | Schema 校验 + 去重 |
| 导出 Excel | 格式化 Excel，3 个 Sheet | 明细 + 统计 + 按模块 |

## 怎么用

### 下载

```bash
git clone https://github.com/HardToThinkAUsername/test-case-engine.git
```

在 Claude Code 中打开此目录，直接对话即可。不需要 `pip install`，不需要配置。

```
我有一份需求文档：req.txt
请帮我按照 test-case-engine 的流程，生成测试用例。
```

AI 会引导你走完完整流程，每个阶段你都可以确认、调整、或推翻重来。

## 核心机制

### 业务树建模

不是直接把需求扔给 AI 生成用例。而是先构建"业务树"——从需求文档中系统性提取所有入口点、追踪业务流程、识别所有分支点。入口点识别有明确的决策树和中文表述模式库，确保不遗漏、不误判。

### L1-L4 分层覆盖

| 层级 | 覆盖什么 | 生成方式 | 要求 |
|------|---------|---------|------|
| L1 | 主路径：每个入口点的正向流程 | 结构化提取 | 100% |
| L2 | 分支路径：每个分支点的每个走向 | 结构化提取 | 100% |
| L3 | 异常模板：10 类异常逐节点匹配 | 模板匹配 | 100% |
| L4 | 想象力场景：10 种增强技术并行挖掘 | 广度追问直至收敛 | 收敛 |

**L3 异常模板（10 类）**：前置条件缺失、输入异常、资源不足、外部依赖失败、并发冲突、超时、权限拒绝、数据不存在、状态非法、空分支。

**L4 想象力技术（10 种）**：逆向思考、反模式学习、渐进式假设、多角色视角、数据全生命周期、逐层追问、类比推理、组合交叉、时序、规模压力。通过 Superpowers `dispatching-parallel-agents` 并行执行，10 个视角独立挖掘，互不污染。

### 5 维度需求评审

在生成用例之前，从完整性、一致性、清晰性、边界性、异常性五个维度评审需求本身。发现的问题在生成用例之前就修复，避免"垃圾进垃圾出"。

### 确认门禁 + Schema 校验

每个阶段有确认门禁——用户不确认，绝不进入下一步。生成后通过 JSON Schema 自动校验（11 个必填字段 + 枚举约束 + 格式约束），不通过不保存。

## 常见问题

**Q: 这个 skill 和直接对 AI 说"帮我写测试用例"有什么区别？**
A: 直接写 AI 会遗漏大量边界场景。这套 skill 有系统的方法论——业务树建模、L1-L4 分层覆盖、5 维度需求评审、10 种想象力增强技术——确保零遗漏、零冗余。

**Q: 需要安装什么？**
A: 不需要。纯对话方式，在 Claude Code 中打开目录即可使用。

**Q: 生成的用例数量是固定的吗？**
A: 不固定。取决于需求文档的复杂度，从几十到几百个。

**Q: 生成的用例在哪里？**
A: `.test-case/test_cases.xlsx`。

**Q: 我能中途调整吗？**
A: 每个阶段都可以。直接告诉 AI 你想怎么改——增加、删除、修改需求，AI 会更新业务树并重新评审。

**Q: 没有 AI 编程助手怎么办？**
A: 推荐安装 Claude Code（https://claude.ai/code）。
