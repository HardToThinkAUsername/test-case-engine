# 测试用例生成宪法

**版本**: 1.0 | **创建日期**: 2026-05-29

---

## 核心目标

**完美** — 零遗漏、零冗余、零误报

---

## 核心原则

### I. 显式引导原则（最高优先级）

**不要假设AI会自己想到，要明确地要求它去想。**

每一个希望AI覆盖的角度，都必须在执行步骤中**显式地、具体地**写出来。

### II. 完整性原则（非协商）

- **必须**识别所有业务入口点
- **必须**追踪所有业务流程，直到叶子节点
- **必须**识别所有分支点
- **必须**覆盖所有场景（L1-L4）

### III. 先广度再深度

- **第一阶段：广度** — 尽可能多地列出所有场景
- **第二阶段：深度** — 对每个场景逐一深入分析
- 遗漏一个场景 = 那个场景完全没被测试

### IV. 零冗余原则（测试用例特有）

- 每个测试用例必须有唯一标识
- 相同测试点的用例必须合并
- 不得生成重复或高度相似的用例

### V. 边界值必须覆盖原则（测试用例特有）

- 每个参数的边界值必须有对应用例
- 边界值包括：最小值、最大值、空值、超长、非法格式
- 每个状态流转的边界必须有对应用例

### VI. 功能测试与性能测试分离原则

- **功能测试**：验证系统功能是否正确实现（业务逻辑、流程、规则）
- **性能测试**：验证系统性能是否满足要求（响应时间、并发、吞吐量）
- 两者**必须分开**，不在同一份用例中混合
- 功能测试用例关注"做什么"，性能测试用例关注"做得多快/多好"

**功能测试场景**：
- 正向流程、分支流程、异常处理
- 业务规则校验、状态流转、数据一致性
- 用户操作响应、界面展示

**性能测试场景**：
- 并发用户数、响应时间、吞吐量
- 大数据量处理、内存占用、CPU使用率
- 网络延迟、超时处理、压力测试

**边界案例判断**：
- "1000并发用户" → 性能测试（不属于功能测试）
- "商品图片10MB" → 性能测试（除非需求明确要求支持大文件）
- "账户锁定后登录" → 功能测试（业务逻辑）
- "验证码重放" → 功能测试（安全逻辑）

## 流程阶段

### 阶段一：需求建模与评审（循环）

```
用户上传需求文档
    → 智能体业务建模
    → 智能体需求评审
    → 输出评审结果
    → 用户语言描述调整
    → 智能体再次评审
    → 循环直到用户满意
```

### 阶段二：测试大纲构建

```
确认后的业务树 + 评审结果
    → 构建测试大纲
    → 输出测试大纲
```

### 阶段三：用例生成

```
测试大纲 + 业务树
    → 逐个场景生成用例
    → 输出用例Excel文档
```

## 场景分层覆盖

| 层级 | 覆盖目标 | 目标 |
|------|----------|------|
| L1 主路径 | 每个入口点的正向流程 | **100%** |
| L2 分支路径 | 每个分支点的每个走向 | **100%** |
| L3 异常模板 | 每个节点匹配异常模板 | **100%** |
| L4 想象力场景 | 通过想象力增强技术生成 | 持续提升 |

### L3 测试异常模板

| 类型 | 模板 |
|------|------|
| 前置条件缺失 | "如果前置条件[条件名]不满足会发生什么？" |
| 输入异常 | "如果输入[参数名]为空/非法/超大会发生什么？" |
| 资源不足 | "如果资源[资源名]不足会发生什么？" |
| 外部依赖失败 | "如果外部依赖[依赖名]失败会发生什么？" |
| 并发冲突 | "如果并发执行会发生什么？" |
| 超时 | "如果操作超时会发生什么？" |
| 权限拒绝 | "如果权限不足会发生什么？" |
| 数据不存在 | "如果数据[数据名]不存在会发生什么？" |
| 状态非法 | "如果状态为[非法状态]会发生什么？" |
| 空分支 | "如果走空分支会发生什么？" |

### L4 想象力增强技术

1. 逆向思考
2. 反模式学习
3. 渐进式假设
4. 多角色视角
5. 数据全生命周期
6. 逐层追问
7. 类比推理
8. 组合交叉
9. 时间和顺序
10. 规模和压力

## 广度追问机制

反复追问直到收敛：

```
第1轮：列出所有你想到的场景
第2轮：从[角色/维度]的角度，还有其他场景吗？
第3轮：历史上类似业务出过哪些问题？是否有对应场景？
第4轮：还有其他吗？请再仔细想想。
```

收敛判断：连续2轮无新增场景。

## 测试用例格式

每个测试用例必须包含：

| 字段 | 说明 |
|------|------|
| 用例编号 | 唯一标识，如TC001 |
| 用例标题 | 简洁描述测试点 |
| 优先级 | P1/P2/P3 |
| 用例类型 | 正向/边界/异常 |
| 来源 | L1/L2/L3/L4 + 具体来源 |
| 前置条件 | 测试执行前需要满足的条件 |
| 操作步骤 | 详细的操作步骤 |
| 预期结果 | 预期的系统行为 |
| 关联需求 | 对应的需求条目 |

---

## 质量标准

| 指标 | 标准 |
|------|------|
| 遗漏率 | **必须 = 0%**（L1-L3） |
| 冗余率 | **必须 = 0%**（无重复用例） |
| 误报率 | **必须 = 0%**（每个用例都有对应需求） |

---

## 治理

宪法优先级最高，所有执行都必须遵循。

违反处理：
- 发现遗漏 → 立即停止 → 输出遗漏报告 → 用户确认 → 修正后重新执行
